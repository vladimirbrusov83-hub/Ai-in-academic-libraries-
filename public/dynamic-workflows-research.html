Dynamic Workflows: How AI Agents Plan Their Own Research — and What It Means for Libraries

A look at how "agentic" AI systems assemble research workflows on the fly, using the Zitnik Lab's biomedical AI agent Biomni as a working example, and what this shift means for research support in academic libraries.

Compiled June 2026 · Companion reading for Level 3: Advanced

What "dynamic" means here

Most of the automation that has reached library workflows so far is what I would call static automation. A Zapier or Make workflow runs the same fixed sequence of steps every time: a form submission triggers an email, a spreadsheet row triggers a notification, a new file triggers a tag. The order of operations is decided in advance, by a human, and the workflow does not deviate from it. This is genuinely useful — Module 14 of this curriculum covers it — but it is not the same thing as the systems now being described as "agentic AI" in research computing.

A dynamic workflow is one where the sequence of steps is not fixed in advance. The system is given a goal — "find the genes most likely to cause this rare disease" or "summarize the recent literature on X and identify research gaps" — and it decides, at run time, what steps are needed, in what order, using which tools, and whether to revise that plan based on what it finds along the way. The plan is a first-class output of the system, not an input to it. For example: a static workflow might always run "search PubMed, then search Web of Science, then deduplicate, then summarize." A dynamic workflow might search PubMed, notice the results are thin, decide on its own to broaden the query or pivot to a different database, and only then move to summarization — adjusting its own plan the way a skilled researcher would.

This distinction matters for libraries because the major scholarly platforms — Web of Science, CAS SciFinder, and others — are rebuilding their AI assistants around exactly this dynamic pattern. Understanding how it works under the hood, in a system where the architecture has been published openly, makes it much easier to evaluate what these vendor tools are actually doing when their interfaces inevitably change.

Case study: the Zitnik Lab and Biomni

The Zitnik Lab at Harvard Medical School, led by Marinka Zitnik, works on AI for medicine and science — knowledge graphs, multimodal models, and increasingly, AI agents that conduct research tasks with a meaningful degree of autonomy. In 2025 the lab released Biomni, described in its preprint as a "general-purpose biomedical AI agent" capable of autonomously executing research tasks across 25 biomedical subfields, from causal gene prioritization and drug repurposing to rare disease diagnosis and microbiome analysis.

What makes Biomni a useful teaching example is not the biomedical content itself — most academic librarians will never need to prioritize a candidate gene — but the architecture, which is published in detail and is a clean illustration of the dynamic workflow pattern in action.

How it plans

Given a research question, Biomni does not select from a library of pre-written workflows. Instead, it generates a plan in plain language — described in the paper as "a clear, numbered bullet-list plan detailing the steps needed to tackle the given problem" — and then works through that plan one step at a time. After each step, it observes the result and revises the remaining plan if needed. If a database query returns nothing useful, the agent does not fail; it adjusts course, the way a person doing a literature search adjusts a query that returns zero results.

How it acts

Each step in the plan is carried out by combining three things: the language model's reasoning, a retrieval step that pulls in the specific tools or databases relevant to that step, and code execution — the agent writes and runs actual Python, R, or Bash code in a sandboxed environment to carry out the task, then reads the output back into its reasoning. This is the "code-based execution" the paper refers to, and it is a meaningful design choice: rather than hardcoding a fixed function for every database (which would make the system brittle and hard to extend), Biomni gives the language model a natural-language interface to each resource and lets it write the specific query needed for the specific step.

How it knows what tools exist

Perhaps the most relevant piece for library work is what the researchers call the action discovery agent. Before Biomni could be useful, the team needed to map out what tools, databases, and protocols actually exist across biomedical research practice. Rather than have a human compile that list by hand, they used an LLM-powered agent to mine thousands of recent research papers, extracting the tasks, tools, databases, and software each paper actually used. Human experts then validated and curated the results into what the paper calls Biomni-E1.

Biomni-E1: the curated action space

2,500bioRxiv papers mined across 25 domains
150specialized tools identified
59databases catalogued

Plus 105 software packages — all discovered by an LLM agent reading the literature, then validated by human domain experts before being made available to Biomni at run time.

I find this last point worth sitting with. The "map" of what tools exist for a domain was itself built by an AI system reading the scholarly literature and extracting practice — and then checked by humans before being trusted. That two-step pattern, AI-assisted discovery followed by human validation, is one I expect to see again and again as these systems move into adjacent fields, including library and information science.

The wider Zitnik ecosystem

Biomni is the most thoroughly documented project, but it sits inside a broader set of tools from the same lab that sketch out where this is headed. ToolUniverse is framed as an effort to "democratize access to AI-driven scientific tools" — essentially, packaging the action space that Biomni-E1 represents so other agents and researchers can use it too. ARK Agent performs what the lab describes as "autonomous knowledge graph exploration with adaptive breadth-depth retrieval" — meaning the agent itself decides, at each step, whether to search broadly across many related concepts or drill down into one in detail, depending on what the question seems to need.

OptimusKG brings biomedical knowledge into a multimodal knowledge graph meant to support "discovery workflows that generate and evaluate biomedical hypotheses" — in other words, a structured map of biomedical knowledge that an agent can reason over, rather than relying purely on what a language model has memorized from training. And Medea, described as an "omics agent," and ClawInstitute, which lets agents "co-develop ideas over time" on shared research boards, point toward multi-agent setups where several specialized agents collaborate over an extended research project rather than answering one query and stopping.

Taken together, the pattern across all of these projects is the same: a structured, queryable map of a domain's knowledge and tools (the knowledge graph and the action space), an agent that can adaptively decide how deeply to explore that map, and a planning loop that revises itself based on what it finds. None of this is specific to biomedicine. It is a general template for how an AI system does research.

The same pattern, arriving in library tools

This is not a hypothetical future for academic libraries — it is already showing up in the discovery platforms libraries license. In April 2025, Clarivate introduced agentic AI into the Web of Science Research Assistant, including a "Literature Review 2.0" guided task. According to Clarivate's own description, the tool "works with the researcher to optimise the search strategy, customize the scope of the task, and define the desired report format, including an introduction, common themes, research gaps and potential hypotheses." Two further agentic guides — Topic Explorer and Find a Journal — followed the same release.

Notice the structure: the system does not simply run one search and summarize the results. It negotiates a plan with the researcher (scope, format), executes a multi-step search-and-retrieve process, and produces a structured output (themes, gaps, hypotheses) — the same plan-act-observe-revise loop that Biomni runs, applied to literature search instead of laboratory protocols. CAS announced a similar direction in October 2025 for SciFinder and BioFinder, describing "intelligent agents trained on scientific content to automate complex research workflows," including a planned literature review agent.

Clarivate has stated that the Research Assistant was developed in partnership with researchers and librarians, and the 2025 Pulse of the Library survey found that librarians identified trust, ethical use, and academic integrity as their top AI priorities, with evaluating AI-generated content as their top literacy need. Read together, this tells me that the vendors building these tools know that librarians are the audience that will be asked, by faculty and students, "can I trust what this gave me?" — and that question only gets harder to answer as the workflow gets more dynamic and less visible.

Knowledge graphs as the backbone

One thread that runs through the Zitnik Lab's work — and that I think is the most directly relevant to digital librarians — is the role of the knowledge graph. OptimusKG and ARK Agent both depend on having a structured, machine-readable map of a domain: entities (genes, diseases, drugs, papers, authors), and the relationships between them (this drug treats this disease, this paper cites this paper, this author is affiliated with this institution). The agent's "adaptive breadth-depth retrieval" is only possible because that map exists in a form the agent can query and traverse.

Academic libraries already build and maintain structured knowledge resources of exactly this kind — institutional repositories, authority files, linked data in catalogs, ORCID-linked author records, subject thesauri. These have historically been built for human discovery: a person searches a catalog, follows a subject heading, finds related works. The Zitnik Lab's work is a preview of a second audience for that same structured data: AI agents that need a reliable map to plan a research workflow, rather than guessing from an unstructured web search. Digital librarians' metadata and linked-data work — long framed as a discovery and preservation function — is also, increasingly, the raw material that makes locally-trustworthy agentic tools possible at all. An agent grounded in an institution's own repository and authority data can answer "what has this institution published on X, and who collaborates with whom" in a way that a general-purpose model, working only from its training data, cannot.

Where this breaks down

Adaptive retrieval is only as good as the map it traverses. A knowledge graph with gaps, outdated relationships, or inconsistent authority control will lead an agent to confidently explore the wrong neighborhood — and because the exploration is dynamic, that error is harder to spot than a single bad search result would be. The quality-control work librarians already do on metadata and authority records is not made obsolete by agentic tools; it becomes more consequential, because it is now an input to automated reasoning, not just to human browsing.

What this means for the librarian's role

I do not think the right response to any of this is to try to learn Biomni, or to expect a community college library to run its own biomedical AI agent. The value of looking closely at a system like this is that it makes the underlying pattern visible in a way that a polished vendor interface does not. When Web of Science's Research Assistant produces a literature review with "themes, gaps, and hypotheses," a librarian who understands the plan-act-observe-revise loop underneath can ask better questions about it: What plan did it follow? What did it search, and in what order? Did it revise its approach partway through, and if so, based on what? Those are the same questions a librarian would ask a research assistant who came back with a literature review — the difference is that the agent's reasoning, in principle, can be inspected, in a way a fixed black-box summary cannot.

This connects directly to the ACRL AI Competencies framework that grounds this curriculum, particularly the Analysis & Evaluation competency area. Evaluating an AI tool used to mean evaluating its outputs. Evaluating a dynamic, agentic tool means also being able to ask about its process — and increasingly, the vendors building these tools are exposing that process (search queries run, sources consulted, plan steps taken) precisely because trust and transparency are the top concerns their librarian customers have raised.

Open questions worth tracking

A few things are still unsettled, and I think they are worth watching rather than treating as solved. First, provenance: as agentic tools chain together more steps autonomously, the chain from "source document" to "final claim in the report" gets longer, and verifying any single link in that chain takes real effort. Second, institutional grounding: most of the agentic tools arriving in library platforms today reason over the vendor's own corpus (Web of Science's index, CAS's databases) rather than an institution's local collections — the knowledge-graph argument above describes a future state, not a current one, for most libraries. Third, cost and access: dynamic, multi-step agent runs consume far more compute than a single search query, and it remains to be seen how that cost is passed through to library subscriptions and to students using free tiers.

None of these are reasons to wait and see. They are reasons to start building the literacy now — for librarians and for the students and faculty who will be handed these tools with very little explanation of how they work.

Key takeaways

  • Dynamic workflows are plans the AI generates itself — a numbered, revisable sequence of steps decided at run time, not a fixed template chosen in advance.
  • Biomni's three-part architecture — LLM reasoning, retrieval of relevant tools/databases, and code execution — is a generalizable template, not a biomedicine-specific one.
  • The action space itself was AI-discovered, then human-validated — 2,500 papers mined to build a curated catalog of 150 tools, 105 packages, and 59 databases. Expect this AI-discovery-then-human-validation pattern elsewhere.
  • Vendor library tools are adopting the same pattern — Web of Science's Literature Review 2.0 and CAS's planned agentic guides both run plan-act-observe-revise loops over scholarly literature.
  • Knowledge graphs are becoming dual-purpose — built for human discovery, but increasingly also the map that agents need to explore reliably. Metadata quality is now an input to automated reasoning, not just browsing.
  • The librarian's evaluative question shifts from output to process — not just "is this answer correct," but "what plan did the agent follow, and can that plan be inspected?"
